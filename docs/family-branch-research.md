# 洞真（dongzhen）族/分支鉴别研究

> 用户原话指出的方向："有一些模型，特别是同系模型相互蒸馏，差别不大，鉴别出指纹后可能是以'族'划分。要更细致，或者研究出分支鉴别的方案。"
> 本文全部结论来自**零成本本地计算**（`tools/confusion_analysis.py`，对 `data/unified_bank.json` 与 648 条参考数据离线分析），未发任何真实 API 请求。
> 复跑方式：`python tools/confusion_analysis.py`（可加库文件路径参数，用于新库回归对比）。

## 1. 库内模型对距离矩阵（数据实锤）

三种距离口径：

- **js_sim**：池化计数直方图的 JS 相似度（1=完全一样）——一阶边缘分布的原始相似度，未去噪；
- **cen_cos**：去噪投影后的模型中心余弦（打分器实际看到的相似度，越接近 1 越难分）；
- **ord_cos**：有序块特征的中心余弦。

### 1.2 三个关键结构性发现

**发现一：GPT 系内部整体比 Claude 系更"挤"。**
- GPT 系 28 对 cen_cos 全部为正，范围 [0.205, 0.506]；Claude 系 45 对范围 [-0.429, 0.651]（一半以上为负）。
- 一阶直方图 js_sim：GPT 系内部 0.89~0.92，Claude 系内部 0.69~0.86，跨族最低 0.70。
- **含义**：GPT 同系变体（sol/astra/luna/terra）的一阶值分布几乎一样，判定的全部信号都在去噪投影后的微弱方向里。用户"同系相互蒸馏、差别不大"的直觉在 GPT 线上完全被数据证实。

**发现二：luna 是一条真实的跨代分支谱系（分支鉴别可行性的最强证据）。**
库外代理（leave-one-model-out，把某模型从库剔除后给它自己的 36 条回答打分）显示：

| 被剔除模型 | 库外归宿 TOP1 | 占比 |
|---|---|---|
| gpt-5.6-luna | **gpt-6-luna**（跨代同分支） | 80% |
| gpt-6-luna | **gpt-5.6-luna**（跨代同分支） | 63% |
| gpt-6-astra | gpt-6-sol（同代异分支） | 56% |
| claude-sonnet-5 | claude-opus-4-8（跨档位） | 94% |

luna 系跨代互指率 80%/63%，远高于其他任何跨代配对——**同分支跨代模型比同代跨分支模型更像**。这说明"分支"是比"版本代际"更自然的分类单位，直接支撑"以族划分"的路线。

**发现三：库外模型可能连家族都判错，"库外强归=垃圾"有实锤。**
- claude-opus-5-5 剔除后 62% 被判成 gpt-5.4（跨族错指）；
- gpt-5.4 剔除后 32% 被判成 claude-opus-5-5；
- claude-sonnet-5-5 剔除后 34% 被判成 gpt-5.6-sol。
库外模型会被 softmax 硬塞给某个库内模型，且不保证同族。任何"库外模型判成了 X"的结论都不可信。

## 2. 现有特征的表达力上限

当前特征 = 0.75 × 一阶值直方图（355 bin，去环境方向） + 0.25 × 有序块（4 位置块 × 16 bin + 尾数 10 bin）。

**能分什么**：一阶直方图捕捉"模型对每个数值的固有偏好"，这是 RLHF/训练数据分布的稳定印记。对**不同训练血统**的模型（不同家族、不同分支）区分力很强——库内自举 k=3 归因正确率 100%，k=1 都有 99.3%。

**不能分什么（理论上限）**：
1. **同分支的 checkpoint / 蒸馏变体**：一阶边缘分布由训练分布决定。同分支蒸馏出的变体如果只是参数量/推理端不同，边缘分布可以完全一致（js_sim 0.92 的 GPT 系内部已经是这个状态的边缘）。此时一阶特征**原理上不可分**，不是数据量问题。
2. **只改采样参数（温度/top_p）的部署变体**：一阶直方图对温度有一定敏感性，但温度效应与"环境噪声"同向，会被去噪投影部分或全部投影掉——去噪是为了跨环境稳健，代价就是把采样参数差异也洗掉了。
3. **有序块的粒度瓶颈**：4 位置块 × 16 bin 是很粗的位置-数值联合统计；相邻取值的相关性（模型"上一个写了 88，下一个回避 88 还是偏爱 88"）完全没有编码——而这恰恰是不同 RLHF 风格最可能留下差异的地方。

**结论**：现有特征对"族级"判定（GPT/Claude、sol/luna/astra/terra 分支）接近够用且仍有余量；对"族内更细的分支变体"（6.1-sol vs 6-sol 这种）已接近表达力天花板，必须升级特征，单纯加题量收益有限。

## 3. 分支鉴别候选方案（按 工作量×预期收益×风险 排序）

### 3.1 功效现状：3 题到底够不够（零成本，已算完）

对每对同族模型算 Cohen's d（融合得分差/合并标准差）与达到 80%/90% 统计功效所需题数：

| 模型对 | d | 80% 功效 | 90% 功效 |
|---|---|---|---|
| claude-opus-4-7 / claude-opus-4-8 | 2.07 | 3.7 题 | 4.9 题 |
| gpt-5.4 / gpt-5.6-sol | 2.31 | 2.9 题 | 3.9 题 |
| gpt-5.4 / gpt-6-astra | 2.39 | 2.7 题 | 3.7 题 |
| gpt-5.6-sol / gpt-6-sol | 2.41 | 2.7 题 | 3.6 题 |
| gpt-5.6-sol / gpt-6-astra | 2.45 | 2.6 题 | 3.5 题 |

（完整 15 对见 `tools/confusion_analysis.py` 输出）

**结论**：GPT 线最难对在 3 题下刚好过 80% 功效线，**没有余量**；claude-opus-4-7/4-8 需要 3.7~4.9 题，3 题不达标。要把"最近的两块指纹"可靠分开（90% 功效），需要 **5 题**（全部同族对 ≤5 题）。

### 3.2 方案排序表

| # | 方案 | 工作量 | 预期收益 | 风险 | API 成本 |
|---|---|---|---|---|---|
| 1 | **诚实协议（ambiguous 输出）** | 无（已落地） | 高：杜绝库外强归误判 | 无 | 0 |
| 2 | **高阶特征升级**（二元组/位置/重复模式） | 中（1~2 天，改特征提取+全库重建） | **高：唯一可能分开族内变体的路径** | 中：高阶特征可能被环境噪声污染，需重新验证去噪策略 | **0**（可从现有 648 条 jsonl 全文重新提取） |
| 3 | **分层判别**（先分支后族内 LRT 似然比） | 中（1 天） | 中高：分支级判定稳健性↑，并给出"不可判对"的似然比口径 | 低：纯统计层改动 | 0 |
| 4 | **动态加题**（unknown 自动加到 5 题） | 小（半天） | 中：把最难对的功效从 80% 拉到 90%+ | 低 | 每次复核 +2 题 ≈ +1.8K token |
| 5 | **分支谱系库**（分支作为一级判定单位） | 小~中（半天~1 天，用现有数据建分支池化中心） | 中：luna 类跨代分支可稳定归支（现状 80%） | 低 | 0 |
| 6 | **多题型集成**（不同挑战类型交叉验证） | 大（新题型设计+全库重采） | 不确定：新题型可能对某些变体更敏感，也可能引入新环境噪声 | 高：改动挑战格式 = 与现库全部口径脱钩 | 高：18 模型 × 3 题/题型 |

### 3.3 各方案要点

**方案 1（已落地）**：库内自匹配 top1-top2 分差 k=3 时 p5=0.78；库外强归分差 p5≤0.104、中位 0.09~0.17。两者之间有 5 倍以上空隙，**阈值 0.40 可以把库外强归几乎全部拦成 unknown**（含全部 18 个库外代理），库内误拦 <5%。已实现在 `api/verdict.py`（`ambiguous_gap_score=0.40`），API 返回 `top_gap` 字段。

**方案 2（高阶特征，推荐主攻）**：候选特征，全部可从现有 jsonl 的回答全文**零成本重提取**：
- 相邻二元组：相邻取值对的联合统计（355×355 太稀，按分箱 35×35 或只算相邻差值分布 |x_{t+1}-x_t|）；
- 位置细粒度统计：把 4 块加细到 8~12 块，或位置×尾数交叉；
- 重复模式：重复值间隔分布（同一个值再次出现的 gap）、最大连击、自相关；
- 数值偏好幅度：一阶直方图的峰值/谷值结构（离均匀分布的偏差谱），而不是只看平滑后的整体形状。

**方案 3（分层判别）**：第一级用现有管线判家族+分支（luna/sol/astra/terra 按名字归支）；第二级在分支内用 LRT/贝叶斯因子比较候选模型，**BF < 10 时直接输出"该分支内不可判对"**。与方案 2 正交，可叠加。6.1 系的场景就是典型受益者：判出 sol 分支（有用信息），同时诚实告知"6.1-sol 与 6-sol 无法区分（库外）"——比强行归一个具体版本有价值得多。

**方案 4（动态加题）**：服务端两段式——3 题初判，若 `top_gap < 0.6`（余量警戒线）自动加 2 题重判。成本：仅对可疑目标 +1.8K token。

**方案 6（多题型）**：留作最后手段。当前证据（发现一、二）表明瓶颈在特征表达力而非题型单一；除非方案 2 的实验显示高阶特征也到顶，否则不值得付全库重采的成本。

## 4. 推荐路线图

### 阶段 0（已完成，本轮）
- 诚实协议进服务（`top_gap` + `ambiguous_gap_score`），库外强归不再硬判。
- 混淆基线工具化：`tools/confusion_analysis.py` 可随时复跑，新库回归对比有基准（本轮全部表格数字）。

### 阶段 1（下一步，零 API 成本，预期 1~2 天）
**高阶特征离线实验**：从现有 648 条 jsonl 提取 §3.3 方案 2 的候选特征，重跑 `confusion_analysis` 口径的自举，对比最难对的 d 值。
- **验证标准**：gpt-5.6-sol/gpt-6-astra（d=2.45）与 claude-opus-4-7/4-8（d=2.07）的 d 提升 ≥2 倍，且 k=1 题自举正确率不降。
- **成本**：0（本地 CPU）。**产出**：一份"哪些高阶特征带分支信号"的实验报告，决定是否重扩建库。

### 阶段 2（零 API 成本，1 天）
**分支谱系判定**：按名字规则把 18 模型归入 4 个 GPT 分支 + Claude 档位，建分支池化中心，实现"先家族 → 再分支 → 族内 LRT"三级输出；服务 verdict 增加 `branch` 字段。
- **验证标准**：库外代理中 luna 系互指率从 80% 提到 95%+；6.1 系场景能稳定输出"sol 分支 + 库外不可定版"。
- **成本**：0。

### 阶段 3（小额成本，随用随付）
**动态加题**：unknown/top_gap<0.6 的目标自动加到 5 题。
- **验证标准**：阶段 0 报告里 3.7~4.9 题才达标的模型对，5 题下自举正确率保持 100% 且分差 p5 升到 1.0+。
- **成本**：每次复核约 +1.8K token（< $0.02，按 $8/M 输出算）。

### 阶段 4（可选，仅在阶段 1 到顶时启动）
**多题型集成试点**：设计 1 种新题型（如降序取值/区间约束），先只对最难对的 4 个模型各采 3 题（12 题 ≈ 11K token ≈ $0.1~0.7），看新题型下这些对的 d 值，再决定是否全库重采。

### 6.1 系入库的决策口径（结合 upstream issue #26）
上游作者结论（6.1-sol 与 6-astra 差异太小、独立特征不稳定）与本研究的发现一致：GPT 系内部一阶分布几乎不可分。**决策建议**：
1. 先按 docs/enrollment.md 满配采 36 条（< $1），用 `tools/confusion_analysis.py` 算它与 gpt-6-sol / gpt-6-astra 的 d；
2. **d ≥ 2 才允许入统一库**；d < 2 只做"分支级登记"（阶段 2 的分支库），不进 softmax 候选集——否则会制造新的混淆对，污染全部既有判定。
